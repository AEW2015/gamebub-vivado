GameBub SDR SDRAM Memory Controller

Version 1.6 | Vivado 2025.2 | GameBub Rev4 / Rev4.1

32 MiB SDR SDRAM with 100 MHz MEM_AXI and unified CTRL_AXI.
Use a separate stable 200 MHz refclk200 for IDELAY calibration.

Board and IPI workflow

  1. For a new project, source board_files/install_gamebub_current_repositories.tcl before and after creating the project, and select GameBub board 1.10 before adding IP. Historical projects retain the full-repository installer until deliberately upgraded.
  2. Add this IP from the catalog. All physical GameBub IP use the same native Board tab; choose the matching interface or Custom.
  3. Bind physical interfaces using board selection and Make External, board-component binding, or the Tcl commands below.
  4. Connect every clock/reset and processor/video interface; assign full address apertures; validate the BD before generating output products.
apply_board_connection -board_interface sdram -ip_intf YOUR_INSTANCE/SDRAM -diagram [current_bd_design]

The built-in xilinx.com:bd_rule:board accepts a fixed list of AMD interface types. Use the explicit binding above for custom GameBub VLNVs; native GPIO/clock automation is separate. Do not modify installed AMD scripts.

Configuration

Memory interface

CTRL_AXI occupies 8 KiB: memory/test registers at +0x0000 and MMCM registers at +0x1000.
The controller contains its own runtime-reconfigurable memory MMCM.

Vitis linker regions

The XSA exports MEM_AXI/Mem as processor-accessible RAM, including instruction access when connected. Vitis 2025.2 default system-device-tree generation does not automatically list these custom controllers in the linker. Use vivado/gamebub_memory_ip/register_app.py with GAMEBUB_MEMORY_XSA, GAMEBUB_MEMORY_WORKSPACE and GAMEBUB_MEMORY_APP environment variables to register the exact XSA RAM windows through the Vitis linker API. This does not move code/data sections or qualify memory hardware. CTRL_AXI registers must never be registered as RAM.

Release boundary

This is a packaging/GUI revision based on 1.5. RTL and electrical/timing constraints are unchanged. GUI validation and synthesis do not qualify external-memory frequency/phase/tap margins, panel appearance, ESP32 lifecycle, or audible/motor behavior. Follow the selected reference build and its timing/hardware evidence.
