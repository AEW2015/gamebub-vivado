GameBub ESP32 QSPI (Standalone)

Version 1.2 | Vivado 2025.2 | GameBub Rev4 / Rev4.1

Standalone ESP32 QSPI service and optional passive sniffer.
Use 50 MHz host_clk for MAILBOX_AXI/SNIFF_AXI, and 200 MHz service_clk.
For a new complete design, prefer the combined ESP32 Communications IP with integrated IRQ gate.

Board and IPI workflow

  1. For a new project, source board_files/install_gamebub_current_repositories.tcl before and after creating the project, and select GameBub board 1.10 before adding IP. Historical projects retain the full-repository installer until deliberately upgraded.
  2. Add this IP from the catalog. All physical GameBub IP use the same native Board tab; choose the matching interface or Custom.
  3. Bind physical interfaces using board selection and Make External, board-component binding, or the Tcl commands below.
  4. Connect every clock/reset and processor/video interface; assign full address apertures; validate the BD before generating output products.
apply_board_connection -board_interface mcu_qspi -ip_intf YOUR_INSTANCE/QSPI -diagram [current_bd_design]
apply_board_connection -board_interface buttons_12bits -ip_intf YOUR_INSTANCE/BUTTONS -diagram [current_bd_design]

The built-in xilinx.com:bd_rule:board accepts a fixed list of AMD interface types. Use the explicit binding above for custom GameBub VLNVs; native GPIO/clock automation is separate. Do not modify installed AMD scripts.

Release boundary

This is a packaging/GUI revision based on 1.1. RTL and electrical/timing constraints are unchanged. GUI validation and synthesis do not qualify external-memory frequency/phase/tap margins, panel appearance, ESP32 lifecycle, or audible/motor behavior. Follow the selected reference build and its timing/hardware evidence.

Upgrade note: invalid overlapping 4 GiB reg0 blocks were removed. Retain/reassign the intended Reg segments. Standalone QSPI BUTTONS now has Master mode to match the board; rebind that interface if upgrading an existing instance. Physical signal directions and register RTL are unchanged.
